# 常設就活コーチの実装と検証

2026年10月20日。

Hermesの通常プロファイルとして就活コーチを動かし、メインの会話とグループから呼ぶサーバー実装を追加した。既存の就活Appと保存処理を維持し、本人情報・訂正・ES・企業情報・旧相談履歴を常設コーチから取得できるようにした。Androidの画面やインストール済みデータは変更していない。

本番は管理者による読み取り専用診断待ち。以下の機能・テストはローカルコードの範囲で確認したもので、本番でのモデル応答・Android実操作の完了を示すものではない。

## コンテクスト取得

### 就活Appの設定操作（2026-10-20の追加修正、本番未反映）

受信先Gmailは企業ごとの項目ではなく、就活App全体で同期する接続済みアカウントの選択である。汎用の`career_propose`はこの接続設定を扱わず、未対応のkindは`invalid_proposal`になる。`career_app`を常設コーチと旧App相談の共通ツールへ追加し、`connections`でAppと同じ接続表示を取得、`mail_account`で受信先と同期の有効・無効を設定、`mail_sender`で企業送信元を設定できるようにした。新しいOAuth接続の作成はGoogle接続画面で行う。

書込は本人の原文とアドレスを照合し、Appの`MailStore`を同じトランザクションで利用する。メール設定の版、企業送信元の版、相談対象の企業、実行中・停止状態を照合し、保存と再実行防止の記録を一括で確定する。受信先を企業送信元へ代用しない。全企業共通の受信先を変えることをツール結果と共通指示に明記し、設定保存と実メール取得成功は区別する。同期停止にはGoogleの再認証を要求しない。

公開ページ取得は、依頼文・保存済み公式URLで許可されたHTTPS origin内の別パスも取得できるようにした。外部origin、認証情報を含むURL、日次実行の公開Web取得への制限は保持する。マイページ入口は既存の`career_save(kind:company_links,type:MyPage)`へ保存し、ログイン設定の完了とは区別する。

検証は一時DBと合成Google接続・合成Hermesホストのみで行った。本番の企業・接続・メール、実Google認証、実モデルの会話は変更・検証していない。

[coach_recall.py](../../server/career/career_core/coach_recall.py)が、既存の保存データと会話を横断して扱う。

- 各カテゴリの全件数と取得の続きを示し、最初の抜粋に含まれない情報も発見できる。
- 本人情報、経験、仮説、ES本文、企業・募集・作業、相談タイトル、過去の発言、引き継ぎ情報を検索・一覧取得できる。
- 日本語の部分一致を扱い、追加の埋め込みAPIや要約モデルを使わない。
- 最初の文脈はカテゴリごとに順番に取り込み、件数の多い一種類だけで埋まらないようにする。
- 本文はIDと文字位置でページ取得できる。取得位置・全文の長さ・続きを返し、長文の末尾まで読める。
- 最新の訂正・利用制限を検索結果と一緒に返す。過去の発言やAIの仮説を、現在の本人事実と区別する。

`career_recall`の引数は`query`、`kind`、`id`、`thread_id`、`offset`、`limit`、`text_offset`。検索語を省けば一覧を取得する。`limit`は最大100件。IDを指定した本文は一回に16,000文字まで返し、`next_text_offset`で原文の続きを取得する。

企業別メール・マイページ案内・設問・未保存の編集中本文は、既存の`career_context`から取得する。初回の文脈で全情報を読み切ったとは扱わず、必要な資料をこの二つのツールで追加取得するよう共通指示を更新した。

旧App側の実行にも同じ検索と目録を追加したため、コンテクスト取得の改善は常設プロフィールだけに閉じていない。

## 個別会話と保存

[native_coach.py](../../server/career/career_core/native_coach.py)が、Hermesの実行前後のhookとCareerの実行状態を接続する。モデルは通常のHermesが一度だけ実行し、旧CoachWorkerへ別Agentの応答を再依頼しない。

実行前に既存の同期と読取版の固定を行い、本人情報・訂正・資料の目録・相談の引き継ぎを渡す。既存の保存・版照合・字数検証・本人発言の引用照合を再利用する。旧ワーカーはnative実行を取得・再実行しない。

新しい会話本文の正本はHermesのstate.db。Careerにはセッションの対応付け、実行・保存状態、本人発言の根拠を保持する。[native_history.py](../../server/career/career_core/native_history.py)は、対応付け済みのセッションだけを読み取り専用で参照する。

`career-coach`プロファイルの表示名は「就活コーチ」。Botの実行主体とCareerのデータ所有者を別に設定する。過去に端末・接続別のprofileへ相談が分かれている場合は、所有者が確認できたものを履歴の参照先へ追加できる。元のprofileや会話IDは書き換えない。

旧相談は従来のApp画面で利用でき、常設コーチから横断参照できる。今回、旧Appの画面をネイティブ会話へ一括で切り替える変更や、過去の全文をHermes DBへ移植する変更は行っていない。

## メインからの依頼

[coach_consult.py](../../server/career/career_core/coach_consult.py)が`career_consult`、`career_consult_status`、`career_consult_stop`を登録する。固定の依頼IDで重複実行を防ぎ、Hermesの既存非同期配送を使って元の会話へ結果を戻す。

モデルが作った依頼文に加え、依頼元の会話を原文で参照できるようにした。原文への参照はホストが確定したprofile・セッション・保存先に限定し、モデルから保存先や所有者を指定させない。

メインの実行前hookで、現在の本人入力を一時的に保持する。相談が実際に依頼された時だけ、その原文を依頼文と分けて引き継ぐ。システム通知や他Agentが作成した要約は、本人発言の保存根拠にしない。

## グループ参加

既存のグループ参加者として`career-coach`を実行する。[group_service.py](../../server/group_chat/group_service.py)から、グループIDと受け付けた本人の発言を、本文のプロンプトと分けて渡す。

短期間・一セッション限定の接続情報をホスト側で発行し、子プロセスの環境を通して受け渡す。プロンプト内のroleやisUserを権限や保存根拠に使わない。接続設定がない場合は別の実行方法へ切り替えず、取得できなかったことを報告する。

旧端末から取り込んだ履歴は閲覧できるが、isUserがtrueというだけでは新しい本人発言の根拠にしない。グループへの委任で生成された追加指示も同じ扱いにする。

## 既存データの保持

既存のentities、文書ファイル、相談本文、会話ID、アーカイブ状態を削除・移動・再作成しない。新しい対応表と実行・出典の管理テーブルを追加する。

インストール処理は既存DBがあることを確認し、SQLiteのbackup機能で復旧用コピーを作る。既存データの件数を前後で照合する。同名の別プロファイルを上書きせず、自分が作成したプロファイルへの再実行も設定を上書きしない。

ローカル作業前の対象ファイルは`output/career-agent-20261020/baseline-024601`へコピーし、内容ハッシュを保存した。既存の未コミット変更は保持している。
