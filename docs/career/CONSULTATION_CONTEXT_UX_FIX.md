# 就活相談のコンテクスト・会話UI修正

## 範囲

既存の文脈保持と会話UIの改善に、企業情報・メール・巡回結果・企業別ログイン設定状態の把握を追加した修正。本人情報の改善を企業情報の改善で置き換えていない。

ユーザーの既存差分、就活データ、会話ID、接続先・プロファイル、アプリID、署名設定を保持。実機のデータ消去、実機・本番サーバーへの反映、pushは行っていない。エミュレーターではテスト用APKをAGPが配置・終了処理し、検証後は今回起動したエミュレーターを終了した。

## 相談コンテクスト

- [企業の準備状況](../../server/career/career_core/company_readiness.py)を、接続設定の有無・ログイン成功の記録・再認証が必要な状態・巡回状態から構成する。認証情報の保存先は開かず、ログインID・パスワード・secret_refをモデルへ渡さない。
- 「取得用の設定がない」と「企業サイトのアカウントが未登録」は別。設定なしは前者、サイト登録は証拠がなければunknown。設定ありも、認証情報の現在の読出可否を保証しない。
- [通常相談の読取ツール](../../server/career/career_core/coach_tools.py)へ企業別概要と保存済みメール・マイページ案内を供給する。一般相談ではcompany_idで企業詳細を読める。企業限定相談では他企業の指定を拒否し、Botだけでなく旧マイページ接続の資料も所有プロファイルで制限する。
- [実行時の初期文脈](../../server/career/career_core/coach_runtime.py)にも本人情報と企業状況の参照プレビューを先に入れる。大きい情報はシリアライズ容量で制限し、プレビューであることと全文取得の必要を明示する。システム文・今回の入力・ツール・出力用の領域も確保する。実モデルの厳密なトークン計測を実施したという意味ではない。
- [同期失敗時の参照](../../server/career/career_core/sharing.py)は、競合がなく以前に検証済みの状態と制約が残る場合だけ、探索・相談用の参考として使用する。最新未確認と明示し、外部提出用の生成・文書保存の制限は保持する。
- 短い会話を一律12ターンで切らず、容量に収まる会話を保持する。大きいツール履歴でも直近の質問と回答を残し、JSONエスケープ分も容量判定する。実行エンジンへ渡す履歴は複製し、永続履歴を限定された入力履歴で上書きしない。
- 保存文書の本文は5件ずつであるため、ページ送りも最小の取得窓に合わせ、途中の文書を飛ばさない。

## 画面

- [会話表示](../../app/src/main/java/com/m57/hermescontrol/career/CareerConversationMessage.kt)は、既存Chatのユーザーバブルと全幅の回答表示を再利用。日時がない互換データへ日時を捏造しない。
- [会話画面](../../app/src/main/java/com/m57/hermescontrol/career/CareerCoachPanel.kt)はコンパクトな入力欄、共有のスクロール制御、初回の最新位置、「最新へ」、過去履歴読込時の位置保持を実装する。
- [状態管理](../../app/src/main/java/com/m57/hermescontrol/career/CareerCoachViewModel.kt)は読込済みの過去メッセージとページ終端を更新・再入場でも保持し、企業と選択資料の参照を通常送信後も引き継ぐ。明示的な参照解除と文書版照合の仕組みは保持する。
- UIと送信処理は同じモデル準備判定を使う。入力は準備確認中にも可能だが、未確認のモデル候補、未対応機能、閲覧専用・アーカイブ状態、未完了の送信を送信可能と表示しない。
- 進捗・エラー・停止・再確認・中断からの続行を会話画面に表示する。既存APIは最終回答を受け取る方式のため「回答は完了後に表示します」と明示する。トークン逐次配信や未提供の添付機能を捏造していない。
- [企業一覧](../../app/src/main/java/com/m57/hermescontrol/career/CareerCompanyScreen.kt)にログイン設定状況と最終巡回成功を表示し、未設定・成功未確認・要確認を別々に絞り込む。設定が必要な企業からその企業の設定へ進める。
- [相談内の企業参照状況](../../app/src/main/java/com/m57/hermescontrol/career/CareerConsultationContextButton.kt)で、保存情報の状態と次の対応を確認できる。画面の最新保存状態と、モデルが実際に全文を読んだことは区別する。件数制限と接続未確認も表示する。

## ローカル検証

- Pythonの関連13スイート205件を最終版で通し実行して成功。実行エンジンによる入力履歴の変更と編集中ES本文の全文再取得の回帰も含む（相談17件）。
- Android就活単体テスト347件（41スイート）成功。Debug APK作成、Debug/Release Kotlin、AndroidTest Kotlin、色リテラル確認も成功した。
- 変更したKotlinファイル17件のみをktlint 1.7.1で整形・確認した。最初の整形で長行が残ったため修正し、再確認が成功した。リポジトリ全体の整形は実施していない。
- Android 16エミュレーターで合成データの画面テスト8件が最終版で成功（失敗・エラー・スキップなし）。モデル準備判定、進捗・エラー・停止、初回最新位置、新着時の読書位置、履歴追加時のアンカー、企業設定への遷移、参照状況、文字サイズ2倍とIMEを確認した。
- 初回の画面検証は4件失敗した。キャプチャ出力をAndroid/dataへ手動指定したアクセス拒否と、クリック可能な企業カードに統合されたセマンティクスのtest fixtureが原因だった。書込可能なAndroid/media出力と、未統合ツリーの実在するラベルを使う検査へ修正し、8件を再実行して成功した。最初の失敗を成功として扱っていない。
- キャプチャは実際のHermesControlThemeとHermesScaffoldを使う合成画面で撮り直し、重なり・読みやすさを目視確認した。[会話画面](../../../output/career-consultation-validation/conversation.png)と[企業参照状況](../../../output/career-consultation-validation/company-context.png)をリポジトリ外へ継続保存した。実企業・実モデルの会話ではない。

既存のテストfixtureも実装契約に合わせた。旧マイページ資料は明示的な所有grantを持たせ、通常送信のUI fixtureには実際に対応したモデル設定を与えた。メールの未成功をnull・fresh:falseで確認し、同期のmockは保存可能な状態オブジェクトを返す。認証・送信のガードを弱めてテストを通していない。

## 未実施・残る確認

実Hermesモデルを用いた回答品質、実企業の登録状態、実OAuthによるメール取得、実巡回結果を使った通し相談、実機での操作は未確認。コードと合成テストの成功は、接続済みの実環境で全企業の状況が確認できたことを意味しない。反映にはAndroid側と就活サーバー側の両方の更新が必要。
