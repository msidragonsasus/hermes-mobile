# 就活App 初版の実装・検証記録

検証日: 2026-09-07〜08（JST）。作業ブランチ: `feat/career-app`。

## 実装範囲

- Appsから開く組込Compose画面。ホーム、企業・募集、応募・作業、自己分析・ES、同期・設定。
- 既存Chatへの相談下書き引き継ぎ。送信は本人操作。保存案は差分確認後に反映。
- Dashboardのcookie認証下で動くcareer APIとHermesツール。SQLite、版番号による競合検出、操作IDによる再試行の重複防止。
- private GitHubの4.0 stateを保った双方向同期、未同期保持、項目単位の競合、訂正履歴、提出版を保持するES保存。4.1は読み取り専用の移行プレビュー。
- Shukatsu転送ファイルの端末内復号と許可項目だけの取り込み。同一出典・版の再取り込みは重複しない。資格情報・メール本文は対象外。
- 公式ページの年度・締切根拠確認、募集変更の記録、応募する場合のタスク作成。手動編集済み締切は公式更新で上書きしない。
- 09:00 JSTの調査timerと5分間隔の同期timerの導入ファイル、実環境の事前確認・バックアップ・復旧手順。

最終ソースで `ktlintCheck`、`checkColorLiterals`、`lintDebug`、`assembleDebug`、`compileReleaseKotlin`、`testDebugUnitTest` が成功。

エミュレーターの画面テストは11件成功（就活画面4件、既存Apps画面2件、ナビゲーション5件）。就活画面では有効化の説明、明示的な応募選択、保存前の差分確認、文字サイズ2倍での操作を検証した。

`final-gates.log` の同時実行では、既存Apps画面の文字サイズ2倍の1件が読み込み待ち10秒でタイムアウトした。テスト・待ち時間・実装を変更せず、画面テスト11件を単独実行した `ui-isolated.log` では全件成功（30秒）。同時実行時のタイムアウト原因は未確定で、検証上の注意として残す。

ログはリポジトリ外の `../career-validation/` に保存。`gates.log` は初回のLint失敗を含む。minSdk 26で使えない `InputStream.readNBytes` を容量制限付きループへ変更し、後続の `ui-gates.log` でLint、スタイル、色指定、APK、Releaseコンパイル、就活画面3件が成功した。初回失敗を成功として扱わない。

## 実環境で未完了の項目

- 既存SSH設定のままBatchModeで接続したが `Permission denied (publickey,password)`。管理者接続ができず、実HEAD・設定・既存ジョブの確認、バックアップ、プラグイン配置、サービス再起動、timer有効化は未実施。
- 稼働Dashboardのhealth応答200と未認証careerパスの401は確認。ただし認証ゲートが未配置パスにも先行し得るため、この401をプラグイン導入済みの証拠にはしない。
- 実Dashboardへのログイン後のcareer API、実Codex OAuth調査、private GitHubの実同期、09:00の無人実行は未確認。
- 指定された実転送ファイルは未復号・未送信。初回取り込みにはMobile画面で本人による合言葉入力が必要。
- エミュレーターの検証のみ。実機への上書き更新、既存実機データの更新前後比較は未実施。アンインストール・データ消去は行っていない。
- GitHubへのpush・PR公開は未実施。個人state、元転送ファイル、認証情報はコード成果物に含めない。

## 初版の制約

公式調査は登録されたHTTPSの公式採用URLを起点とする。ログイン必須ページ、PDF、JavaScriptだけのページ、HTTP redirectには未対応で、失敗を表示し既存情報を保持する。根拠文字列の存在を検証しても、募集内容の意味が正確かどうかは実データで確認が必要。時刻不明の締切に23:59などを補わない。

4.1移行の適用は既存ChatGPT側との互換確認後の別工程。現在の4.0を勝手に移行しない。サーバーは既存Dashboardの利用者・プロファイルに従う個人用保存領域で、複数利用者を分離するサービスとしては設計していない。

導入と復旧の手順: [career README](../../server/career/README.md)。
