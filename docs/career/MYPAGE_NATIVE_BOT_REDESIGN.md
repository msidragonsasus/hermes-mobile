# マイページ確認：既存Botと標準ブラウザへの切替

2026-09-21。追加ログインを行わず、既存認証を維持するというユーザー指示を優先する。
本番切替・実企業の取得成功は別途確認する。この文書はローカル実装・検証の記録。

## 構成

既存 `career-mypage` プロファイル、Gateway、会社単位Cronジョブ、モデル設定、認証解決を使う。
Cron子プロセスは既存の `coach_runtime.make_agent` からHermes AIAgentを起動する。
新しいプロファイル、Gateway、モデルログイン、認証ファイルの複製は追加しない。
当初検討した別プロファイルのAgent付きCron移行は、追加認証が必要になるため取り下げた。

| 担当 | 実装 |
|---|---|
| 定期・手動・排他・履歴 | 既存 `mypage_cron` / `mypage_job` を再利用。日本時間9時・18時 |
| モデル設定・既存認証・無料接続制限 | 既存 `ExecutionPolicy` / `model_credentials` / `make_agent` を再利用 |
| ブラウザ起動・活動管理・終了 | Hermes標準browserツールとAIAgentの終了処理 |
| 認証入力 | `career_mypage_auth`。標準agent-browserの暗号化された一時auth vault。パスワードはstdin |
| 読取 | 標準navigate / snapshot。clickは確認済みリンク先への標準navigateに限定し、onclick送信を防ぐ |
| 保存 | `career_mypage_record`。実際のpage_id・URL・原文引用を検証し、既存DBへ都度保存 |

独自Playwright子プロセス、CDP接続、ブラウザ維持スレッド、寿命延長、別の終了処理は新経路から除外する。
Careerは読取限定の制限、秘密情報非露出、保存の整合だけを担当する。ページの指示は実行しない。
標準Agentへ32ターン・480秒を設定し、有料モデルや補助モデルへの自動切替を無効化する既存処理を使う。

## 接続単位の移行

接続の `config.engine=standard` だけで新経路を選ぶ。既存ジョブIDを変えず、同時に旧経路を呼ばない。
未移行接続は旧経路のまま。既存接続の編集でもengineとジョブIDを保持する。
切替は非稼働状態で行い、認証情報・設定の版・過去の保存結果を保持する。
日鉄で取得・保存・表示を確認するまではEY・JR東海・アビームを対応済みにしない。

## 途中結果と計測

各案内の出典を都度保存する。中断時に保存済み案内があれば一部取得、なければ取得失敗。
0件正常完了には認証後ページの実際の「該当なし」等の原文が必要。
追加認証や認証失敗は自動反復を止める。原文不一致、別企業・別実行からの操作、応募操作を拒否する。
ログには実行ID・固定処理名・時間・成否・例外型・コード位置だけを出す。本文・Cookie・認証値は出さない。
モデル通信とブラウザ操作の時間を別々に記録する。本番の速度改善率はまだ算定しない。

## 反映手順

導入済みソースのハッシュ、モデル設定、接続の版、停止中の実行、DB整合を照合する。
同じサーバーの標準ブラウザでダミー試験後、バックアップ付きで対象コードだけを差し替える。
既存サービスを再開し、日鉄の既存Cronを1回だけ実行する。追加ログイン・モデル変更・依存更新は行わない。
サーバーの結果とApp用viewを確認したうえで、実機表示を確認する。
