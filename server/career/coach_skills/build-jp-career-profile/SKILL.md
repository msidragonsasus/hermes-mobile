# 経験と行動特性を発掘する

自己分析を宿題にせず、会話から素材を作る。実績の大きさではなく、本人の判断、行動、修正、証拠密度を重視する。

## 読むもの

現在の依頼に必要な参照だけ読む。本人事実を扱うときは証拠規約、対話では質問規約を確認する。状態に依存する最初の処理でstate-management、実際の接続・読書込でgithub-chat-storageを読む。state-patchは変更・復旧、移行資料とv3資料は該当作業時だけ読む。Pythonが使える場合の素材選択・再開確認には `scripts/coaching_state.py`、4.0読込には `scripts/migrate_state_v40.py` を使える。通常Chatでの実行を仮定しない。

`references/evidence-policy.md`、`references/question-policy.md`、`references/state-management.md`、`references/github-chat-storage.md`、`references/state-patch.md`、`references/privacy-policy.md`、`references/profile-discovery.md`

## 手順

1. private GitHub v4の既知の本人事実、story、hypothesisを先に確認し、同じ事実を聞き直さない。未接続でも探索は進める。
2. 棚卸しのまとめを求められた場合は既知の経験候補を比べる。探索中や候補が出ない場合は、次の小さな経験から答えやすい一問を選ぶ。
   - 続けたこと、変えたこと、誰かを助けたこと
   - 失敗して修正したこと、面倒でも仕組みにしたこと
   - 選択を迫られたこと、周囲と調整したこと
   - 日常で繰り返している工夫
3. 話された経験の場面、本人と他者の役割、判断理由、変化を分ける。比較を求められたときは判断の具体性、修正、証拠密度等を用い、肩書や成果規模だけで順位を付けない。
4. 探索は原則一問ずつ。本人の回答に応じて、判断・代替案・反例など次の問いを変える。ESや強みラベルの確定へ急がない。
5. 本人が直接確認した内容は `FACT-###` 候補、未確認の清書表現は `INFERRED/UNKNOWN`（source_role=GENERATED_DOCUMENT）、共通する行動特性は `HYP-###` として分ける。
6. 素材をまとめる段階で`ST-###`とfact_idsで関連づける。探索の途中でstory完成を強制しない。未知の数字・感情・対立・因果を補わない。
7. 行動特性の仮説ごとに、支持事実、反証、次に観測する場面を置く。本人確認前は推論のままにする。
8. 確認済みfact、根拠付きstory、再開checkpointを保存対象にする。本人が採用・保存を望んだ解釈はhypothesisのまま分離する。write-through同意があればSHA-safeに保存する。失敗時は`UNSAVED_JOBHUNT_PATCH_V4`を返す。Local v3互換時だけ従来patchを使う。

## 出力

探索中は問いと必要な短い整理だけ。以下は棚卸しのまとめを求められたときの確認項目で、毎回の必須出力ではない。

1. **既知の経験候補**
2. **比較表**
3. **上位候補の深掘り質問**（最大3問）
4. **FACT候補 / HYPOTHESIS候補**
5. **素材化したストーリー**
6. **行動特性の仮説と反証**
7. **使える設問 / 足りない証拠**
8. **状態パッチのプレビュー / 未保存差分**

「何もしていない」を額面どおりに能力評価へ変換しない。小さくても本人の選択と修正が見える経験を探す。
