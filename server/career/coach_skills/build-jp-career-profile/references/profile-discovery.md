# 経験発掘フレームワーク

自己分析の目的は「立派な肩書を探すこと」ではなく、本人が繰り返す判断・行動・修正を、根拠付きで発見することにある。

## 候補を探す領域

- 大学・ゼミ・授業・研究・資格学習
- 部活・サークル・学生団体・委員会
- アルバイト・インターン・家業・ボランティア
- 受験・進路変更・失敗・中断・再挑戦
- 個人開発・創作・趣味・ゲーム・SNS・コミュニティ
- 家事、移動、健康管理、予定管理など日常の工夫
- 誰かを教えた、助けた、調整した、断った経験

「実績がない」と言われた場合、賞・役職・売上だけを探さない。本人が何を見て、何を選び、何を変えたかを探す。

## 候補比較

各候補を5段階で機械採点して正解を決めない。次の観点を相対比較する。

| 観点 | 見るもの | 弱いときの追加質問 |
|---|---|---|
| 主体性 | 本人が選んだ部分 | 指示された中で何を自分で決めたか |
| 判断の具体性 | 選択肢と理由 | 他に何ができ、なぜそれを選ばなかったか |
| 証拠密度 | 記録、観察、第三者反応 | 何を見れば変化を確認できるか |
| 修正 | 失敗、観測、変更 | 最初のやり方と何を変えたか |
| 変化 | 本人・相手・仕組みの前後差 | 数字がなくても何が起きなくなったか |
| 再現性 | 別場面でも表れたか | 同じ行動特性が出た別の場面はあるか |
| 深掘り耐性 | 口頭で具体化できるか | 面接で聞かれると困る空白は何か |

成果規模、知名度、役職は補助情報であり、本人性を代替しない。

## 深掘り質問の優先順位

1. 本人の役割と他者の役割を分ける質問
2. 判断理由と代替案を確認する質問
3. 行動前後の変化を確認する質問
4. 失敗・修正を確認する質問
5. 数字の出典を確認する質問

探索は原則一問ずつ、回答に応じて次問を変える。質問への返答待ちでよく、毎回の候補比較・素材化は不要。本人が素材をまとめたいと求めたときに、確認済み範囲で整理する。

## ストーリー形式

```markdown
## ST-001 | 経験名 | CONFIRMED / DRAFT

- 期間・状況:
- 本人の立場:
- 目標・必要性:
- 課題・制約:
- 選択肢:
- 判断と理由:
- 本人の行動:
- 他者の行動:
- 観測した変化:
- 失敗・修正:
- fact_ids（本人と他者の役割・場面を混ぜずに対応）:
- 根拠・参照:
- 行動特性の仮説:
- 反証になり得る事実:
- 未確認:
- 使える設問:
- 適用範囲付き不採用decisionと再確認事項:
```

本人が確認するまで、行動特性は `INFERRED` とする。
