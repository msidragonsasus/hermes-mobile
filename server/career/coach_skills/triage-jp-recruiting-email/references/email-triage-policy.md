# 採用メール整理ポリシー

## 対象範囲を最小化する

検索例:

- 期間: `newer_than:30d`
- 送信元ドメイン・企業名
- 件名: 選考、面接、提出、予約、結果、インターン
- ラベルまたは受信箱

「就活メール全部」のような依頼でも、まず期間と関連語で絞る。重要メールを判定するには、ラベルの `IMPORTANT` ではなく本文上の期限・要対応・結果を読む。

## 抽出項目

- 企業名、職種・コース、卒年
- 件名、送信日時、送信元表示名
- 通知種別: deadline / interview / event / result / action_required / information
- 絶対日時とタイムゾーン
- 要対応、必要物、URL
- 既存案件との一致・不一致
- メール固有の更新か、公式情報でも確認できるか

## 権限境界

- 検索・読取の依頼は、台帳更新、返信、ラベル変更、アーカイブ、削除の許可を含まない。
- 台帳反映は「反映して」「更新して」等の明示依頼がある場合だけ。
- 返信は別の明示依頼で行い、対象スレッドを先に読む。
- ワンタイムコード、パスワード、ログインリンクの資格情報を保存・再掲しない。

## 衝突

公式ページ、既存台帳、メールで締切が違う場合、勝手に上書きしない。各出典と受信日時を示し、応募者個別メールが最新更新である可能性を `INFERRED` として扱う。

## 出力の最小化

本文全文を再掲せず、意思決定に必要な要点と差分だけを示す。メールアドレスは目的に必要な場合以外マスクする。
