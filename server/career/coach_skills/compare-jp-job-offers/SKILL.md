# 内定・進路を比較する

点数表だけで決めず、確認済み条件、必須条件違反、下振れ、情報価値、期限を分けて意思決定する。

## 読むもの

現在の依頼に必要な参照だけ読む。本人事実を扱うときは証拠規約、対話では質問規約を確認する。状態に依存する最初の処理でstate-management、実際の接続・読書込でgithub-chat-storageを読む。state-patchは変更・復旧、移行資料とv3資料は該当作業時だけ読む。Pythonが使える場合の素材選択・再開確認には `scripts/coaching_state.py`、4.0読込には `scripts/migrate_state_v40.py` を使える。通常Chatでの実行を仮定しない。

1. `references/offer-decision-policy.md`
2. `references/evidence-policy.md`
3. `references/question-policy.md`
4. `references/state-management.md`
5. `references/github-chat-storage.md`
6. `references/state-patch.md`
7. 最新情報を調べる場合は `references/web-research-policy.md`

## 手順

1. 比較対象、承諾・辞退期限、本人の必須・希望・除外条件を確定する。
2. 企業ごとに、職種、配属確度、勤務地、転勤、処遇、働き方、育成、事業耐久性、海外機会、選考中の観測を `CONFIRMED / INFERRED / UNKNOWN` で分ける。
3. 未確認で結論が反転する項目だけを調査・質問する。期限が近ければ暫定判断も同時に出す。
4. 必須条件違反と、合理的な上振れを含めても他案に全面的に劣る選択肢を先に除く。
5. ベース、上振れ、下振れの3ケースと、3年後・10年後の選択肢の広さ、辞退後に戻せない度合いを比較する。
6. 重み付き評価を使う場合は、重みの感度と合計点が逆転する条件を示す。点数だけで推奨を決めない。
7. 推奨、反転条件、追加情報の価値、期限までの確認・交渉・意思決定手順をまとめる。
8. applications、tasks、hypotheses、decisionをv4候補として分け、write-through同意があればSHA-safeに保存する。未保存時は`UNSAVED_JOBHUNT_PATCH_V4`を返す。
9. 承諾・辞退・期限延長依頼の外部送信は、本人の明示依頼と最終文面確認なしに行わない。

## 出力

1. **確認済み比較表**
2. **必須条件違反・未確認事項**
3. **ベース / 上振れ / 下振れ**
4. **推奨と反転条件**
5. **承諾期限までの確認・交渉・意思決定手順**
6. **状態パッチのプレビュー / 決定ログ追記候補**

期限が近くても、不明な条件を推測で埋めない。推奨は現時点の証拠に基づく暫定判断として示す。
