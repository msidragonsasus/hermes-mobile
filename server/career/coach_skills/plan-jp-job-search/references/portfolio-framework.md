# 応募ポートフォリオ設計

応募先は「企業の魅力度ランキング」ではなく、本人条件、準備能力、選択肢価値を含むポートフォリオとして設計する。

## 先に分ける条件

- **必須**: 満たさなければ原則応募しない
- **希望**: 満たすほど優先度が上がる
- **除外**: 明確に避ける条件
- **探索仮説**: 実際に参加・面談しないと判断できないもの

年収、勤務地、海外機会、配属、転勤、AI代替リスク等は同じ確度で扱わない。公式に確認できる制度と、将来予測・配属実態の推論を分ける。

## ポートフォリオ役割

| 役割 | 意味 | 注意 |
|---|---|---|
| 挑戦 | 難度は高いが上振れ価値が大きい | 全件を挑戦枠にしない |
| 中核 | 条件・興味・準備可能性のバランスが良い | 最も準備資産を配分する |
| 安全網 | 相対的に選考可能性を確保する | 「安全」を断定せず根拠と不確実性を示す |
| 探索 | 業界・職種仮説を検証する | 情報価値が下がれば早く切る |

## 比較軸

- 必須条件の充足
- 本人の確認済み経験との接続
- 業務・顧客・価値提供への関心
- 参入障壁、業務変化、AIによる補完・代替の経路
- 勤務地、配属、転勤、海外機会の不確実性
- 選考時期と競合案件
- ES・Webテスト・面接の準備負荷
- 他社にも再利用できる準備資産
- インターン参加による情報価値・優遇可能性
- 落ちた場合・受けない場合の機会損失

## 件数の上限

応募可能件数は、企業数ではなく必要タスクの総時間で決める。

```text
週の応募容量 = 可処分時間 - 固定予定 - 回復余白 - 既存面接準備
```

各社について最低限、調査、ES、Webテスト、面接準備の見積りを置く。容量を超える場合は、低い情報価値、重い独自選考、条件不一致から削る。

## 推奨の出し方

- 暫定順位であることを明示する
- 各社に「推す理由」「落とす条件」「未確認」「次の調査」を付ける
- 最新募集が見つからない企業を、募集中として扱わない
- 本人条件に関係しない知名度・人気だけで上位に置かない
