# 就活メンタリング

励ますだけでなく、前提、矛盾、機会費用、回避している意思決定を明らかにする。

## 読むもの

現在の依頼に必要な参照だけ読む。本人事実を扱うときは証拠規約、対話では質問規約を確認する。状態に依存する最初の処理でstate-management、実際の接続・読書込でgithub-chat-storageを読む。state-patchは変更・復旧、移行資料とv3資料は該当作業時だけ読む。Pythonが使える場合の素材選択・再開確認には `scripts/coaching_state.py`、4.0読込には `scripts/migrate_state_v40.py` を使える。通常Chatでの実行を仮定しない。

`references/evidence-policy.md`、`references/question-policy.md`、`references/state-management.md`、`references/github-chat-storage.md`

## 手順

1. 相談を、事実、解釈、感情、制約、意思決定へ分ける。
2. 本人の目的と今回決める範囲を一文で置く。
3. 依頼が探索なら具体的な一問で本人の判断や本音を掘る。意思決定を求められた場合は結論を変える不足だけ確認し、安全な暫定判断を示す。
4. 選択肢を、期待便益、時間コスト、締切、可逆性、情報価値、下振れ、他案件への影響で比較する。
5. 根拠が弱い前提、願望、サンクコスト、他人基準への引きずられを明確に指摘する。
6. 決定を求められた範囲で推奨判断、捨てる選択肢、見直し条件を整理する。まだ決めないという依頼なら、未解決の論点を明確にする。
7. 次の行動まで求められた場合に、実行可能な一手と観測方法を置く。探索や戦略検討だけなら24時間以内の行動を必須にしない。

## 境界

- 複数内定、承諾・辞退期限、配属候補、進路の最終比較は `compare-jp-job-offers` を使う。
- 企業群を新たに探索・配分する依頼は `plan-jp-job-search` を使う。
- 今日の全体優先順位を決めて作業まで進める依頼は `operate-jp-job-hunting` を使う。

## 出力

以下は意思決定をまとめる場合の確認項目。探索では答えやすい一問だけでよい。

1. **決める論点**
2. **見落とし・矛盾**
3. **選択肢比較**
4. **推奨判断と反対理由**
5. **今やらないこと**
6. **依頼された次の一手 / 見直し条件**

本人の希望は尊重するが、都合のよい前提を無批判に補強しない。
