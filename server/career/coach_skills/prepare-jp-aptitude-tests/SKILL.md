# 適性検査を準備する

合格保証や流出問題への依存ではなく、残り時間と誤答原因に基づく再現可能な準備へ変える。

## 読むもの

現在の依頼に必要な参照だけ読む。本人事実を扱うときは証拠規約、対話では質問規約を確認する。状態に依存する最初の処理でstate-management、実際の接続・読書込でgithub-chat-storageを読む。state-patchは変更・復旧、移行資料とv3資料は該当作業時だけ読む。Pythonが使える場合の素材選択・再開確認には `scripts/coaching_state.py`、4.0読込には `scripts/migrate_state_v40.py` を使える。通常Chatでの実行を仮定しない。

`references/evidence-policy.md`、`references/question-policy.md`、`references/state-management.md`、`references/github-chat-storage.md`、`references/web-research-policy.md`、`references/assessment-integrity.md`、`references/aptitude-test-framework.md`

## 手順

1. 企業・コース、受検期限、案内文、会場・自宅、所要時間、既知の提供元、現在の練習結果を確認する。
2. テスト名や形式は案内文・公式情報を優先する。URLや過去例だけで断定せず、`confirmed / likely / unknown` を付ける。現在変わり得る形式は公式情報で確認する。
3. 準備中か、本番・監督下・採点対象の実施中かを区別する。本番中は個別問題の答えを出さず、終了後の復習または同概念のオリジナル類題へ切り替える。
4. 言語、計数・非言語、論理、英語、速度、操作慣れを、正答率、時間、誤答原因で診断する。性格検査は一貫した自己回答を尊重し、企業向けの偽装を勧めない。
5. 期限までの可処分時間から、優先領域、学習単位、模試日、休止条件を決める。教材名を挙げる場合は、現行版・提供元・費用を確認する。
6. 練習では著作権・非公開設問を複製せず、オリジナル類題を一問ずつ出す。回答後に、知識不足、読解、立式、計算、時間配分、操作ミスへ分類する。
7. 必要ならv4 tasks用に、期限、所要時間、完了条件が一つの学習taskへ分解する。保存できない場合は未保存差分を返す。

## 出力

1. **形式判定と確度**
2. **受検期限・制約**
3. **弱点診断**
4. **期限までの学習計画**
5. **今回の類題または演習**
6. **誤答ログと次の一手**
7. **未確認事項**
