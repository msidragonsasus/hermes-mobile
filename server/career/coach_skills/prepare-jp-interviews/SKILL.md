# 新卒面接を準備・練習する

## 読むもの

現在の依頼に必要な参照だけ読む。本人事実を扱うときは証拠規約、対話では質問規約を確認する。状態に依存する最初の処理でstate-management、実際の接続・読書込でgithub-chat-storageを読む。state-patchは変更・復旧、移行資料とv3資料は該当作業時だけ読む。Pythonが使える場合の素材選択・再開確認には `scripts/coaching_state.py`、4.0読込には `scripts/migrate_state_v40.py` を使える。通常Chatでの実行を仮定しない。

`references/evidence-policy.md`、`references/question-policy.md`、`references/state-management.md`、`references/github-chat-storage.md`、`references/interview-framework.md`

## モード

- **設計**: リスク、想定質問、回答骨子、逆質問を作る
- **ドリル**: 特定テーマを反復する
- **模擬面接**: 一問ずつ進める
- **デブリーフ**: 実施直後の事実を記録し、retrospectへ渡す

## 手順

1. 面接段階、企業・職種・コース、形式、時間、提出資料、既知傾向を確認する。
2. 該当企業・応募の提出資料と関連fact、story、訂正、不採用条件、過去観測を読む。提出済みESの旧主張を現在の本人事実へ戻さず、訂正に関係する部分だけ再確認する。
3. 質問ごとに、面接官が確認し得る能力・リスクを一言で示す。意図を断定しない。
4. 回答骨子は確認済み事実だけで作る。未知の事実を流暢な模範回答で埋めない。
5. 口頭で自然に言える短い主張、根拠、判断、結果、学びへ整理する。
6. 模擬面接では最初の質問だけを出し、回答後に回答性、具体性、本人性、論理、企業接続、深掘り耐性を評価する。先に模範回答を与えすぎない。
7. 逆質問は公開情報で答えが出る質問を避け、本人の入社判断仮説へ接続する。
8. 一度の練習結果から弱みを確定せず、繰り返し観測された傾向を仮説として記録する。

## 出力

通常:
1. **面接リスク**（最大5点）
2. **想定質問と確認意図**
3. **回答骨子**
4. **深掘りに必要な事実**
5. **逆質問**
6. **練習計画**

模擬面接では一問だけ出し、ユーザーの回答を待つ。
